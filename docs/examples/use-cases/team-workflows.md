# Team Workflows

Examples of using ansible-craft in team environments.

## Overview

This guide covers workflows for teams using ansible-craft to:
- Share configuration defaults
- Review generated code
- Maintain consistency
- Collaborate on Ansible automation

## Shared Configuration

### Project-Level Defaults

Create a shared configuration for the team:

```bash
# In project root
mkdir -p .ansible-craft
```

Create `.ansible-craft/defaults.toml`:

```toml
# Shared team defaults - commit to repo

[defaults.role]
platforms = ["ubuntu", "debian"]
ansible_version = "2.14"
require_privilege = true
molecule = true
ci_provider = "github"

[defaults.playbook]
inventory_groups = ["webservers", "databases", "loadbalancers"]
connection = "ssh"
become = true
```

Team members can use these defaults:

```bash
# Copy to user config (one-time setup)
cp .ansible-craft/defaults.toml ~/.config/ansible-craft/config.toml

# Then use --quick
ansible-craft new role "nginx" --quick
```

### Per-Project Claude Code Setup

For Claude Code users, install skills project-locally:

```bash
# In project root
ansible-craft setup --project
git add .claude/
git commit -m "chore: add ansible-craft Claude Code integration"
```

This ensures all team members have the same slash commands available.

## Code Review Workflow

### Generate → Review → Merge

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Generate   │────▶│   Review    │────▶│   Merge     │
│  in Branch  │     │   via PR    │     │  to Main    │
└─────────────┘     └─────────────┘     └─────────────┘
```

### Step 1: Create Feature Branch

```bash
git checkout -b feat/add-nginx-role
```

### Step 2: Generate Role

```bash
ansible-craft new role "nginx reverse proxy with SSL" -o roles/
```

### Step 3: Review Generated Code

Before committing, review:
- Task logic and ordering
- Variable names and defaults
- Template correctness
- Handler definitions

```bash
# Review generated files
cat roles/nginx/tasks/main.yml
cat roles/nginx/defaults/main.yml
```

### Step 4: Create Pull Request

```bash
git add roles/nginx/
git commit -m "feat: add nginx role generated by ansible-craft"
git push origin feat/add-nginx-role
```

### PR Template

Create `.github/PULL_REQUEST_TEMPLATE/generated_role.md`:

```markdown
## Generated Role Review

**Role:** <!-- e.g., nginx -->
**Generated with:** `ansible-craft new role "description"`

### Checklist

- [ ] Reviewed task logic
- [ ] Verified variable defaults
- [ ] Checked template syntax
- [ ] Ran ansible-lint locally
- [ ] Tested with Molecule (if applicable)

### Changes Made Post-Generation

<!-- List any manual modifications -->

### Testing Notes

<!-- How to test this role -->
```

## Role Library Management

### Centralized Role Repository

```
ansible-roles/
├── nginx/
├── postgresql/
├── redis/
├── common/
├── Makefile           # Generation and testing commands
├── requirements.yml   # Role dependencies
└── README.md
```

### Makefile for Team Operations

```makefile
# Makefile

.PHONY: generate lint test

# Generate a new role
# Usage: make generate ROLE="nginx with SSL" NAME=nginx
generate:
	@if [ -z "$(ROLE)" ]; then echo "Usage: make generate ROLE='description' NAME=name"; exit 1; fi
	ansible-craft new role "$(ROLE)" -n "$(NAME)" -o . --fix

# Lint all roles
lint:
	ansible-lint */

# Test all roles with Molecule
test:
	@for role in */; do \
		if [ -d "$$role/molecule" ]; then \
			echo "Testing $$role"; \
			(cd $$role && molecule test); \
		fi \
	done

# Generate documentation
docs:
	@for role in */; do \
		echo "# $$role" >> ROLES.md; \
		cat "$$role/README.md" >> ROLES.md; \
		echo "" >> ROLES.md; \
	done
```

## Naming Conventions

### Role Naming

Establish team conventions:

| Type | Convention | Example |
|------|------------|---------|
| Service roles | `<service>` | `nginx`, `postgresql` |
| Platform roles | `<platform>_<component>` | `aws_ec2`, `gcp_gke` |
| Utility roles | `common_<purpose>` | `common_security`, `common_users` |

### Variable Naming

```yaml
# Use role name as prefix
nginx_port: 80
nginx_ssl_enabled: true
nginx_worker_processes: auto

# Not this
port: 80  # Too generic, conflicts with other roles
```

### Task Naming

```yaml
# Sentence case, descriptive
- name: Install nginx package
- name: Deploy nginx configuration template
- name: Enable and start nginx service

# Not this
- name: install nginx  # Not sentence case
- name: nginx          # Not descriptive
```

## Review Checklist

### For Reviewers

When reviewing generated roles:

**Tasks:**
- [ ] Tasks are in logical order
- [ ] All tasks have meaningful names
- [ ] Handlers are used appropriately
- [ ] No hardcoded values that should be variables

**Variables:**
- [ ] Defaults are sensible
- [ ] Required variables are documented
- [ ] Sensitive variables noted for vaulting

**Templates:**
- [ ] Template syntax is correct
- [ ] Variables in templates exist
- [ ] File permissions are appropriate

**Metadata:**
- [ ] Role dependencies are declared
- [ ] Supported platforms are listed
- [ ] Galaxy metadata is complete

**Tests:**
- [ ] Molecule tests cover main functionality
- [ ] Tests are idempotent

## Standardization

### Shared Prompts

Create a library of standard prompts:

```
docs/prompts/
├── nginx.md      # Standard nginx generation prompt
├── postgresql.md # Standard postgresql prompt
└── common.md     # Patterns and conventions
```

Example `docs/prompts/nginx.md`:

```markdown
# Nginx Role Generation

## Standard Prompt

```
nginx reverse proxy with:
- SSL termination using Let's Encrypt
- Gzip compression for text content
- Rate limiting (10 requests/second)
- Access logging in JSON format
- Custom error pages
- Security headers (HSTS, X-Frame-Options, etc.)

Target: Ubuntu 22.04 and Debian 12
```

## Variables to Expect

- `nginx_ssl_enabled`
- `nginx_domains`
- `nginx_rate_limit`
- `nginx_backends`
```

### Automation Standards

Document what should always be included:

```markdown
# Team Standards

## All Roles Must Have

1. **Defaults** - All configurable values in `defaults/main.yml`
2. **Handlers** - Service restarts via handlers, not tasks
3. **Tags** - All tasks tagged appropriately
4. **Documentation** - README with examples
5. **Tests** - Molecule tests for CI

## Variables

- Prefix with role name: `rolename_variable`
- Use snake_case
- Document in README

## Generation Flags

Always use:
- `--fix` to auto-fix lint issues
- Review all generated code before committing
```

## Onboarding New Team Members

### Setup Checklist

```markdown
# New Team Member Setup

1. [ ] Install ansible-craft: `npm install -g ansible-craft`
2. [ ] Configure API key: `ansible-craft config save`
3. [ ] Copy team defaults: `cp .ansible-craft/defaults.toml ~/.config/ansible-craft/config.toml`
4. [ ] Install Claude Code integration: `ansible-craft setup --project`
5. [ ] Read team standards: `docs/standards.md`
6. [ ] Generate a test role to verify setup
```

### First Task Template

```markdown
# Your First Generated Role

1. Create a branch: `git checkout -b feat/your-role`
2. Generate: `ansible-craft new role "description" -o roles/ --quick`
3. Review the generated code
4. Make any necessary adjustments
5. Run lint: `ansible-lint roles/your-role/`
6. Commit and create PR
7. Address review feedback
```
