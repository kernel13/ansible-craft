# Phase 4: Role Generation - Research

**Researched:** 2026-01-19
**Domain:** Ansible role structure, FQCN compliance, idempotency patterns, YAML generation, prompt engineering
**Confidence:** HIGH

## Summary

- **Ansible role structure** is well-defined by Galaxy standards: tasks/, handlers/, defaults/, vars/, templates/, files/, meta/, README.md, plus molecule/ for testing
- **FQCN (Fully Qualified Collection Names)** are mandatory for ansible-lint compliance - use `ansible.builtin.*` for all core modules; canonical names only, no aliases
- **Idempotency** requires explicit state declarations (`state: present`, `state: started`), using built-in modules over command/shell, and leveraging handlers for conditional restarts
- **Structured outputs** via Anthropic API beta (`structured-outputs-2025-11-13`) can guarantee JSON schema compliance for plan previews, but YAML generation works best via prompt engineering with explicit examples
- **Two-phase generation** (plan preview then full generation) aligns with CONTEXT.md decisions and enables user modification before committing to code output

**Primary recommendation:** Use a two-stage prompt architecture: (1) structured JSON output for plan preview with schema validation, (2) streaming YAML generation with embedded FQCN patterns and idempotency examples in the system prompt.

## Ansible Role Structure

The Galaxy-standard role structure must be generated completely:

```
role_name/
├── README.md              # Galaxy-ready documentation (REQUIRED)
├── defaults/
│   └── main.yml          # Default variables (lowest precedence, user-overridable)
├── vars/
│   └── main.yml          # Internal role variables (higher precedence)
├── tasks/
│   └── main.yml          # Main task entry point (REQUIRED)
├── handlers/
│   └── main.yml          # Event-triggered tasks (service restarts)
├── templates/
│   └── *.j2              # Jinja2 templates (config files, etc.)
├── files/
│   └── *                 # Static files to copy
├── meta/
│   └── main.yml          # Role metadata for Galaxy (REQUIRED)
└── molecule/
    └── default/
        ├── molecule.yml  # Test configuration
        ├── converge.yml  # Main test playbook
        └── verify.yml    # Post-converge verification
```

### Directory Purposes

| Directory | Purpose | Contents |
|-----------|---------|----------|
| `defaults/` | User-overridable settings | Variables with sane defaults, lowest precedence |
| `vars/` | Internal role state | Variables not meant to be overridden |
| `tasks/` | Automation logic | The actual Ansible tasks |
| `handlers/` | Event responses | Tasks triggered by `notify:` |
| `templates/` | Dynamic config files | Jinja2 templates, `.j2` extension |
| `files/` | Static assets | Files copied as-is |
| `meta/` | Role metadata | Galaxy info, dependencies, platforms |
| `molecule/` | Testing | Molecule test scenarios |

## FQCN Reference

All generated tasks MUST use Fully Qualified Collection Names. Using short names (e.g., `apt`) triggers ansible-lint warnings.

### Core ansible.builtin Modules by Category

**Package Management:**
| FQCN | Purpose |
|------|---------|
| `ansible.builtin.apt` | Debian/Ubuntu packages |
| `ansible.builtin.dnf` | RHEL 8+/Fedora packages |
| `ansible.builtin.yum_repository` | Yum repo management |
| `ansible.builtin.apt_repository` | Apt repo management |
| `ansible.builtin.apt_key` | APT GPG keys |
| `ansible.builtin.rpm_key` | RPM GPG keys |
| `ansible.builtin.package` | Generic (auto-detects manager) |
| `ansible.builtin.pip` | Python packages |

**File Operations:**
| FQCN | Purpose |
|------|---------|
| `ansible.builtin.file` | Files, directories, permissions |
| `ansible.builtin.copy` | Copy files to remote |
| `ansible.builtin.template` | Render Jinja2 templates |
| `ansible.builtin.lineinfile` | Single line in file |
| `ansible.builtin.blockinfile` | Multi-line block in file |
| `ansible.builtin.stat` | Get file info |
| `ansible.builtin.unarchive` | Extract archives |
| `ansible.builtin.get_url` | Download files |

**Service Management:**
| FQCN | Purpose |
|------|---------|
| `ansible.builtin.service` | Generic service control |
| `ansible.builtin.systemd_service` | Systemd units specifically |

**User/Group:**
| FQCN | Purpose |
|------|---------|
| `ansible.builtin.user` | User accounts |
| `ansible.builtin.group` | Groups |

**Command Execution (use sparingly):**
| FQCN | Purpose |
|------|---------|
| `ansible.builtin.command` | Run command (no shell features) |
| `ansible.builtin.shell` | Run with shell interpretation |

**Control Flow:**
| FQCN | Purpose |
|------|---------|
| `ansible.builtin.include_tasks` | Dynamic task inclusion |
| `ansible.builtin.import_tasks` | Static task import |
| `ansible.builtin.include_vars` | Load variable files |
| `ansible.builtin.set_fact` | Set runtime variables |
| `ansible.builtin.debug` | Print debug info |
| `ansible.builtin.fail` | Fail with message |
| `ansible.builtin.assert` | Validate conditions |

### FQCN Enforcement Rules

1. **Always use canonical names** - `ansible.builtin.copy`, not `copy`
2. **No aliases** - `ansible.builtin.package`, not `ansible.builtin.yum` for generic use
3. **Collections prefix** - For community modules: `community.general.ufw`, `community.docker.docker_container`
4. **No `collections:` keyword** - Always use full FQCN in each task

### Example Task with FQCN

```yaml
---
# Correct - FQCN used
- name: Install nginx
  ansible.builtin.apt:
    name: nginx
    state: present
    update_cache: true

# Incorrect - short name
- name: Install nginx
  apt:
    name: nginx
    state: present
```

## Idempotency Patterns

Idempotent tasks produce the same result regardless of how many times they run.

### Core Principles

1. **Explicit state declaration** - Always specify `state: present/absent/started/stopped`
2. **Use built-in modules** - They handle idempotency internally
3. **Avoid command/shell** - Not idempotent by default
4. **Use handlers** - For service restarts after config changes

### Idempotent Patterns

**Package Installation:**
```yaml
- name: Install packages
  ansible.builtin.apt:
    name:
      - nginx
      - certbot
    state: present
    update_cache: true
    cache_valid_time: 3600  # Don't update if cache < 1 hour old
```

**File/Directory Creation:**
```yaml
- name: Ensure config directory exists
  ansible.builtin.file:
    path: /etc/nginx/conf.d
    state: directory
    owner: root
    group: root
    mode: '0755'
```

**Template Deployment with Handler:**
```yaml
- name: Deploy nginx configuration
  ansible.builtin.template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    owner: root
    group: root
    mode: '0644'
    validate: nginx -t -c %s
  notify: Reload nginx

# In handlers/main.yml
- name: Reload nginx
  ansible.builtin.service:
    name: nginx
    state: reloaded
```

**Service Management:**
```yaml
- name: Ensure nginx is running and enabled
  ansible.builtin.service:
    name: nginx
    state: started
    enabled: true
```

**When command/shell is necessary - use `creates` or `changed_when`:**
```yaml
- name: Run one-time setup script
  ansible.builtin.command:
    cmd: /opt/setup/initialize.sh
    creates: /opt/setup/.initialized  # Only runs if file doesn't exist

- name: Check certificate status
  ansible.builtin.command:
    cmd: certbot certificates
  register: cert_status
  changed_when: false  # Never marks as changed
```

### Anti-Patterns to Avoid

| Anti-Pattern | Why Bad | Better Approach |
|--------------|---------|-----------------|
| `shell: apt install nginx` | Not idempotent, no error handling | Use `ansible.builtin.apt` |
| Missing `state:` parameter | Ambiguous intent | Always specify state |
| `command: service nginx restart` | Always restarts | Use handler with notify |
| `shell: echo "line" >> file` | Duplicates on re-run | Use `lineinfile` |
| `when: result|failed` after command | Shouldn't need to recover | Use proper module |

## YAML Best Practices

### Formatting Rules (ansible-lint compliant)

1. **2-space indentation** - Never tabs
2. **Named tasks** - Every task must have a `name:` field
3. **Boolean format** - Use `true`/`false`, not `yes`/`no`
4. **Quote strings with special characters** - `"{{ variable }}"` not `{{ variable }}`
5. **Multiline strings** - Use `|` (literal) or `>` (folded) block scalars
6. **List format** - Multi-line preferred for readability

### Quoting Rules

```yaml
# Variables need quotes to avoid YAML parsing issues
- name: Set variable value
  ansible.builtin.set_fact:
    my_var: "{{ some_variable }}"

# Strings starting with special chars need quotes
- name: Task with special string
  ansible.builtin.debug:
    msg: "{{ item }} - processed"

# Numbers vs strings
port: 8080        # Integer
port_str: "8080"  # String

# Boolean values
enabled: true     # Correct
enabled: yes      # Deprecated in newer ansible-lint
```

### Multiline Strings

```yaml
# Literal block (preserves newlines)
config_content: |
  server {
      listen 80;
      server_name example.com;
  }

# Folded block (newlines become spaces)
description: >
  This is a long description that spans
  multiple lines but will be rendered
  as a single line.

# For shell commands
- name: Complex shell command
  ansible.builtin.shell: |
    set -e
    cd /opt/app
    ./configure
    make install
```

### Task Ordering Convention

```yaml
---
# 1. Variables/facts first
- name: Set installation facts
  ansible.builtin.set_fact:
    install_dir: /opt/app

# 2. Package installation
- name: Install required packages
  ansible.builtin.apt:
    name: "{{ packages }}"
    state: present

# 3. User/group creation
- name: Create application user
  ansible.builtin.user:
    name: appuser
    system: true

# 4. Directory structure
- name: Create directories
  ansible.builtin.file:
    path: "{{ item }}"
    state: directory
  loop:
    - /opt/app
    - /opt/app/config

# 5. Configuration files
- name: Deploy configuration
  ansible.builtin.template:
    src: config.yml.j2
    dest: /opt/app/config/config.yml
  notify: Restart app

# 6. Service configuration
- name: Enable and start service
  ansible.builtin.service:
    name: app
    state: started
    enabled: true
```

const systemPrompt = `You are an Ansible expert generating production-ready roles.

1. **Be explicit about format** - Include example YAML in system prompt
2. **Constrain output** - "Output valid YAML only, no markdown code blocks"
3. **Embed patterns** - Show correct FQCN usage in examples
4. **Validate incrementally** - Check YAML validity as it streams
5. **Context depth matters** - Include platform info if clarified via questions

## Implementation Considerations

### Output Parsing Strategy

Generated content uses file markers that can be parsed:

```typescript
interface GeneratedFile {
  path: string;      // "tasks/main.yml"
  content: string;   // YAML content
}

function parseGeneratedContent(output: string): GeneratedFile[] {
  const fileRegex = /=== PATH: (.+?) ===([\s\S]*?)=== END ===/g;
  const files: GeneratedFile[] = [];

  let match;
  while ((match = fileRegex.exec(output)) !== null) {
    files.push({
      path: match[1].trim(),
      content: match[2].trim(),
    });
  }

  return files;
}
```

### YAML Validation

Validate generated YAML before writing:

```typescript
import { parse } from 'yaml';

function validateYaml(content: string, filePath: string): boolean {
  try {
    parse(content);
    return true;
  } catch (error) {
    console.error(`Invalid YAML in ${filePath}:`, error.message);
    return false;
  }
}
```

### File Writing Strategy

Per CONTEXT.md decisions:
- Default: `./role-name/` in current directory
- `--output` flag for custom directory
- `--name` flag to override inferred name
- `--dry-run` for preview without writing
- Prompt on existing directory (unless `--force`)

```typescript
interface WriteOptions {
  roleName: string;
  outputDir: string;
  dryRun: boolean;
  force: boolean;
}

async function writeRole(files: GeneratedFile[], options: WriteOptions): Promise<void> {
  const roleDir = path.join(options.outputDir, options.roleName);

  if (await exists(roleDir) && !options.force) {
    const overwrite = await confirm(`Directory ${roleDir} exists. Overwrite?`);
    if (!overwrite) return;
  }

  for (const file of files) {
    const filePath = path.join(roleDir, file.path);
    await mkdir(path.dirname(filePath), { recursive: true });

    if (!options.dryRun) {
      await writeFile(filePath, file.content);
    }
    console.log(`${options.dryRun ? '[DRY RUN] ' : ''}Created: ${file.path}`);
  }
}
```

### Edge Cases

1. **Empty directories** - Create with `.gitkeep` for git tracking
2. **Invalid role name** - Sanitize: lowercase, hyphens, no special chars
3. **Very long descriptions** - Truncate for role name inference
4. **Template variables** - Ensure Jinja2 syntax is valid
5. **Multi-OS support** - Generate conditionals with `ansible_os_family`
6. **Existing files** - Clear directory on overwrite, don't leave orphans
