<task type="auto">
  <name>Task 1: Create custom help formatter</name>
  <files>src/cli/help.ts</files>
  <action>
Create gh-style custom help formatting that extends Commander's Help class.

1. Create src/cli/help.ts:
   - Import { Command, Help } from 'commander'
   - Import chalk from 'chalk'

2. Create CustomHelp class extending Help:
   - Override formatHelp(cmd: Command, helper: Help): string
   - Structure output in sections:
     * USAGE section with command pattern
     * COMMANDS section (will be populated in later phases)
     * OPTIONS section with flags
     * EXAMPLES section with 2-3 usage examples

3. Style the output:
   - Section headers in bold cyan (chalk.bold.cyan)
   - Command names in green (chalk.green)
   - Option flags in yellow (chalk.yellow)
   - Example command prompts dimmed (chalk.dim('$'))
   - Respect NO_COLOR automatically (chalk handles this)

4. Include these examples in help:
   ```
   $ ansible-craft new role "install nginx with SSL"
   $ ansible-craft explain roles/webserver/tasks/main.yml
   $ ansible-craft fix "FAILED! Authentication failed"
   ```

5. Export formatHelp function for use in configureHelp:
   ```typescript
   export function formatHelp(cmd: Command, helper: Help): string {
     return new CustomHelp().formatHelp(cmd, helper);
   }
   ```
  </action>
  <verify>
- File exists and exports CustomHelp class
- TypeScript compiles without errors
- formatHelp function is exported
  </verify>
  <done>
- src/cli/help.ts exists with CustomHelp class
- Help output has USAGE, OPTIONS, EXAMPLES sections
- Styling uses chalk with colored headers
  </done>
</task>

<task type="auto">
  <name>Task 2: Create version display and wire up help/version</name>
  <files>src/cli/version.ts, src/cli/program.ts</files>
  <action>
Create version display with environment info and integrate help/version into program.

1. Create src/cli/version.ts:
   - Import chalk and boxen
   - Read version from package.json (import with assert type json OR use Bun.file)

2. Create getVersionInfo() function returning object:
   - version: from package.json
   - runtime: Bun.version if available, else process.version
   - os: `${process.platform}-${process.arch}`

3. Create displayVersion() function:
   - Format version info as multi-line string
   - Wrap in boxen with padding: 1, borderStyle: 'round'
   - Output to stdout via console.log

4. Update src/cli/program.ts:
   - Import { formatHelp } from './help.js'
   - Import { displayVersion } from './version.js'

5. Configure help:
   ```typescript
   program.configureHelp({
     formatHelp: formatHelp,
     sortSubcommands: true,
     sortOptions: true,
   });
   ```

6. Configure version to use custom display:
   ```typescript
   program
     .version('0.1.0', '-V, --version', 'display version information')
     .action(() => {
       // This is the default action when no subcommand given
     });
   ```

   Note: For custom version display, use option() instead:
   ```typescript
   program.option('-V, --version', 'display version information');
   ```
   Then check for version flag before parseAsync and call displayVersion().

7. Handle no-arguments case:
   - After parseAsync, check if no subcommand was invoked
   - If process.argv.length <= 2, call program.help()
   - Alternative: use program.showHelpAfterError() plus check
  </action>
  <verify>
- `bun run dev --help` shows custom formatted help with examples
- `bun run dev --version` shows version in boxed format with runtime info
- `bun run dev` (no args) shows help output
  </verify>
  <done>
- Version displays: version number, runtime (Bun), OS info
- Help shows USAGE, OPTIONS, EXAMPLES sections with colors
- No-arguments invocation shows help
  </done>
</task>
