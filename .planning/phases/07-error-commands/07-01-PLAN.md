   interface RoleFile {

   }

   - Read each file content with readFile(filePath, 'utf-8')
   - Also check for README.md in root (type: 'meta')
   - Return array of RoleFile objects

4. Create inferFileType(filePath: string): RoleFile['type']
   - Check if path contains known subdirs (tasks/, handlers/, etc.)
   - Default to 'playbook' for standalone .yml files

Use async/await throughout. Handle ENOENT errors gracefully (skip missing subdirs).

<task type="auto">
  <name>Task 2: Context extractor for --playbook flag</name>
  <files>src/explain/context-extractor.ts</files>
  <action>
Create smart context extraction that provides relevant context without overwhelming the prompt.

Implementation:
1. Define ContextExtraction interface:
   ```typescript
   interface ContextExtraction {
     variables: Record<string, unknown>;  // From defaults/, vars/
     handlers: string[];                   // Handler names only
     taskContext: string;                  // ±5 lines around failing task
     roleStructure?: string;               // Directory listing for role explanation
   }
   ```

2. Create extractContext(playbookPath: string): Promise<ContextExtraction>
   - Use readAnsiblePath() to read all files
   - Extract variables from defaults/main.yml and vars/main.yml using yaml.parse()
   - Extract handler names via regex: /name:\s+([^\n]+)/g from handlers/
   - Build roleStructure string showing directory tree if it's a role

3. Create extractFixContext(errorMessage: string, playbookPath: string): Promise<ContextExtraction>
   - Parse task name from error using multiple regex patterns:
     - /TASK \[(.*?)\]/ (standard format)
     - /"task": "(.*?)"/ (JSON format)
     - /The task includes an option with an undefined variable.*?"(.*?)"/ (undefined var)
   - Find the task in files by matching task name
   - Extract ±5 lines around the matching task (or full task if >15 lines)
   - Get referenced variables and handlers as above

4. Create parseTaskNameFromError(errorMessage: string): string | undefined
   - Try each regex pattern in order
   - Return first match or undefined

5. Create findTaskInFiles(taskName: string, files: RoleFile[]): { file: RoleFile; lineIndex: number } | undefined
   - Search through files for task name (handle quoted/unquoted)
   - Return file and line number if found

Use yaml package for parsing (already in deps). Handle parse errors gracefully (return empty objects).
  </action>
  <verify>
Test extraction:

- extractFixContext with "TASK [Install nginx]" error finds the task
- parseTaskNameFromError extracts task names from various error formats
