<task type="auto">
  <name>Task 1: Create ansible-lint subprocess wrapper</name>
  <files>src/generation/validation/ansible-lint.ts</files>
  <action>
Create ansible-lint.ts with:

1. **Types**:
   - `LintViolation`: { ruleId: string, level: 'error' | 'warning', message: string, file: string, line?: number, column?: number }
   - `AnsibleLintResult`: { violations: LintViolation[], exitCode: number, available: boolean }

2. **isAnsibleLintAvailable()**: Check if ansible-lint is installed
   - Spawn `ansible-lint --version` with stdout/stderr piped
   - Return true if exitCode === 0, false otherwise
   - Wrap in try/catch for ENOENT errors

3. **runAnsibleLint(targetPath: string)**: Execute lint and return results
   - First check availability, return early with available: false if not installed
   - Spawn `ansible-lint --format sarif --nocolor <targetPath>`
   - Pipe stdout/stderr, await proc.exited
   - Parse SARIF JSON from stdout using parseSarifResults()
   - Return { violations, exitCode, available: true }

4. **parseSarifResults(sarifJson: string)**: Parse SARIF format
   - Handle empty/invalid JSON gracefully (return empty array)
   - Extract from runs[0].results array
   - Map each result to LintViolation: ruleId, level, message.text, locations for file/line

5. **formatInstallInstructions()**: Return helpful install message
   - Include `pip install ansible-lint` command
   - Note minimum version recommendation (6.0+)

Use Bun.spawn (not child_process) per research recommendations.
Defensive parsing: handle missing optional SARIF fields gracefully.
  </action>

Create a simple test file in /tmp, verify isAnsibleLintAvailable() returns boolean.

  </verify>
