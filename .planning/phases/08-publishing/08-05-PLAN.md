# ansible-craft

Generate production-ready Ansible roles and playbooks from natural language descriptions. Powered by Claude AI.

[![npm version](https://img.shields.io/npm/v/ansible-craft.svg)](https://www.npmjs.com/package/ansible-craft)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

## Features

- **Role Generation**: Create complete Ansible roles with tasks, handlers, defaults, templates, and meta
- **Playbook Generation**: Generate full playbooks with plays, tasks, handlers, and inventory
- **Error Explanation**: Get plain-English explanations of existing Ansible code
- **Error Fixing**: Interpret Ansible errors and get fix suggestions with corrected code
- **Quality Assurance**: All generated code uses FQCN, follows idempotency patterns, and passes ansible-lint
- **Streaming Progress**: See generation progress in real-time
- **Dry-run Preview**: Preview what will be created before writing files

## Installation

### Global Install (Recommended)

```bash
# npm
npm install -g ansible-craft

# yarn
yarn global add ansible-craft

# pnpm
pnpm add -g ansible-craft
```

### Run Without Installing

```bash
# npx
npx ansible-craft --help

# bunx
bunx ansible-craft --help

# pnpx
pnpx ansible-craft --help
```

## Quick Start

1. **Set up your API key**:

```bash
ansible-craft config save
```

Or set the environment variable:

```bash
export ANTHROPIC_API_KEY=your-api-key
```

2. **Generate a role**:

```bash
ansible-craft new role "install nginx with SSL and virtual hosts"
```

3. **Generate a playbook**:

```bash
ansible-craft new playbook "deploy LAMP stack with WordPress"
```

## Commands

### `new role <description>`

Generate a new Ansible role from a natural language description.

```bash
ansible-craft new role "install nginx with SSL and virtual hosts"
```

Options:
- `-o, --output <dir>`: Output directory (default: current directory)
- `-n, --name <name>`: Role name (default: inferred from description)
- `--dry-run`: Preview without writing files
- `--force`: Overwrite existing directory without prompting
- `--fix`: Auto-fix lint violations without prompting
- `--no-interactive`: Skip clarifying questions
- `-q, --quiet`: Suppress progress output
- `--json`: Output results in JSON format (for CI/CD)

### `new playbook <description>`

Generate a new Ansible playbook from a natural language description.

```bash
ansible-craft new playbook "deploy LAMP stack with WordPress"
```

Options: Same as `new role`

### `explain <file>`

Get a plain-English explanation of an Ansible file.

```bash
ansible-craft explain roles/nginx/tasks/main.yml
```

Options:
- `--complex`: Use Claude Opus for more detailed analysis

### `fix <error-message>`

Interpret an Ansible error and get fix suggestions.

```bash
ansible-craft fix "The task includes an option with an undefined variable"
```

Options:
- `--playbook <file>`: Provide playbook context for better suggestions
- `--complex`: Use Claude Opus for difficult problems
- `--apply`: Apply the fix automatically (prompts for confirmation)

### `config`

Manage CLI configuration.

```bash
# Show current configuration
ansible-craft config show

# Save configuration interactively
ansible-craft config save
```

### `completions <shell>`

Generate shell completion scripts.

```bash
# Bash
ansible-craft completions bash >> ~/.bashrc

# Zsh
ansible-craft completions zsh >> ~/.zshrc

# Fish
ansible-craft completions fish > ~/.config/fish/completions/ansible-craft.fish
```

## Configuration

Configuration is stored in `~/.ansible-craft/config.toml`:

```toml
[api]
key = "your-anthropic-api-key"
model = "claude-sonnet-4-20250514"

[generation]
lint = true
```

### Environment Variables

- `ANTHROPIC_API_KEY`: Your Anthropic API key (required)

## Generated Code Quality

All generated code follows Ansible best practices:

- **FQCN (Fully Qualified Collection Names)**: Uses `ansible.builtin.*` module names
- **Idempotency**: Tasks are safe to run multiple times
- **ansible-lint compliance**: Passes standard linting rules
- **Proper structure**: Follows Ansible Galaxy role structure
