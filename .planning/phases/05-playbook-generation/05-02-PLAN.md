<task type="auto">
  <name>Task 1: Create playbook system prompt</name>
  <files>src/generation/prompts/playbook-system.ts</files>
  <action>
Create new file with playbook-specific system prompt.

**Structure the prompt with these sections:**

1. **Intro** - "You are an Ansible expert generating production-ready playbooks."

2. **FQCN Section** - Copy from `system.ts` (same 27 module examples). This is identical for roles and playbooks.

3. **Idempotency Patterns** - Copy from `system.ts` (same rules apply).

4. **YAML Formatting Rules** - Copy from `system.ts` (same rules).

5. **Playbook Structure** (NEW - replace Role Structure):
```
playbook_name/
├── playbook.yml          # Main playbook (REQUIRED)
├── inventory.example     # Example inventory (REQUIRED)
├── group_vars/
│   ├── all.yml           # Global variables (REQUIRED)
│   └── [group].yml       # Per-group variables
└── README.md             # Usage instructions (REQUIRED)
```

6. **Play Organization** (NEW):
   - Multiple plays for different host groups
   - Play execution order: pre_tasks -> tasks -> handlers -> post_tasks
   - pre_tasks usage: variable validation, fact gathering, prerequisite checks
   - post_tasks usage: service health verification, smoke tests
   - Handlers defined per-play, not global

7. **Inline Tasks with Role Extraction Hints** (NEW):
   - Show comment pattern: `# Could be extracted to role: nginx`

8. **group_vars Organization** (NEW):
   - Section headers: `# Network settings`
   - Per-group files matching inventory groups

9. **inventory.example Format** (NEW):
   - INI format with groups matching playbook hosts patterns
   - Include [group:vars] examples
   - Include [all:vars] for ansible_python_interpreter

10. **Multi-Host Patterns** (NEW):
    - become: per task, not play-level
    - serial: as commented example with explanation
    - Delegation only when clearly needed

11. **Content Depth** (NEW):
    - Validation in pre_tasks with assert/fail
    - Verification in post_tasks with uri/wait_for
    - Comments explain "why" not "what"

Export as `ANSIBLE_PLAYBOOK_SYSTEM_PROMPT`.

Reference 05-RESEARCH.md "System Prompt for Playbooks" section for exact content.

  <name>Task 2: Create playbook plan and generate prompts</name>
  <files>src/generation/prompts/playbook-plan.ts, src/generation/prompts/playbook-generate.ts</files>
  <action>
Create two new files for plan and generation prompts.

**playbook-plan.ts:**

Create `buildPlaybookPlanPrompt(description: string, clarifications?: Record<string, string>): string`

The prompt should instruct Claude to:
1. Analyze the description for deployment scenario
2. Identify required host groups (webservers, databases, etc.)
3. Plan plays with pre_tasks, tasks, post_tasks as appropriate
4. Identify variables to put in group_vars
5. Return structured JSON matching PlaybookPlanPreview schema

Include these sections:
- User's description
- Instructions to plan plays by host group
- Emphasis on validation in pre_tasks
- Reminder to use FQCN in task modules
- If clarifications provided, include them

**playbook-generate.ts:**

Create `buildPlaybookGeneratePrompt(plan: PlaybookPlanPreview, description: string): string`

Import PlaybookPlanPreview type from `../schemas/playbook-plan.js`

Build prompt sections:
1. Original Request - the description
2. Approved Plan - formatted from plan object
   - Playbook Name, Description, Inventory Groups
   - Plays (in execution order) with tasks, handlers, pre/post_tasks flags
   - Group Variables organized by group
3. Output Format - file marker instructions
   - `=== PATH: playbook.yml ===` then content then `=== END ===`
   - Same for inventory.example, group_vars/all.yml, group_vars/[group].yml, README.md
4. Required Files list
5. Reminders (FQCN, become per task, handlers per play, etc.)

Reference 05-RESEARCH.md "Generation Prompt Template" section for exact format.
