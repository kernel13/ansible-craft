  <name>Task 1: Install Zod and create wizard types with schemas</name>
  <files>package.json, src/wizard/types.ts</files>
  <action>
Install Zod and create the wizard type definitions with Zod validation schemas.

1. Install Zod dependency:
   ```bash
   bun add zod
   ```

2. Create `src/wizard/` directory if not exists

3. Create `src/wizard/types.ts` with:

**RoleStructureDirectory union type:**
- 'tasks' | 'handlers' | 'templates' | 'files' | 'defaults' | 'vars' | 'meta'

**RolePlatform union type:**
- 'Ubuntu' | 'RHEL' | 'Debian' | 'Windows' | 'Generic'

**RoleHandler union type:**
- 'restart' | 'reload' | 'enable' | 'custom'

**RoleWizardContext interface (all required):**
- structure: RoleStructureDirectory[] - selected directories
- platforms: RolePlatform[] - target platforms
- handlers: RoleHandler[] - handler types needed
- custom: Record<string, string> - extensibility field for future data

**PlaybookWizardContext interface (all required):**
- hosts: string[] - inventory groups to target
- become: boolean - privilege escalation needed
- includeHandlers: boolean - include handlers in playbook
- custom: Record<string, string> - extensibility field

**Zod schemas (strict mode, no coercion):**
- roleStructureDirectorySchema: z.enum for directories
- rolePlatformSchema: z.enum for platforms
- roleHandlerSchema: z.enum for handlers
- roleWizardSchema: z.object with .strict() - validates RoleWizardContext
- playbookWizardSchema: z.object with .strict() - validates PlaybookWizardContext

Export TypeScript types inferred from Zod schemas using z.infer<> for consistency.
Export both interfaces and schemas.

Follow project patterns:
- Use JSDoc comments on interfaces and functions
- Use union types for enums (matching src/config/schema.ts pattern)
- All fields required (per CONTEXT.md decision)
  </action>

- `bun run lint` passes

<task type="auto">
  <name>Task 2: Implement formatForPrompt functions</name>
  <files>src/wizard/types.ts</files>
  <action>
Add formatter functions that convert wizard context to clarifications format.

1. Add to `src/wizard/types.ts`:

**formatRoleContextForPrompt(context: RoleWizardContext): Record<string, string>**
- Returns terse key-value pairs for token efficiency
- Format arrays as comma-separated strings
- Keys match what prompt builders expect:
  - 'structure': comma-separated directories (e.g., "tasks, handlers, templates")
  - 'platforms': comma-separated platforms (e.g., "Ubuntu, RHEL")
  - 'handlers': comma-separated handler types (e.g., "restart, reload")
- Only include custom fields if non-empty

**formatPlaybookContextForPrompt(context: PlaybookWizardContext): Record<string, string>**
- Returns terse key-value pairs
- Keys:
  - 'hosts': comma-separated inventory groups
  - 'become': "yes" or "no" (Ansible convention)
  - 'handlers': "include" or "exclude"
- Only include custom fields if non-empty

Return type is `Record<string, string>` to match existing clarifications parameter in:
- generateRolePlan(client, description, clarifications?: Record<string, string>)
- buildPlanPrompt(userDescription, clarifications?: Record<string, string>)

Follow formatting pattern from src/generation/prompts/plan.ts lines 30-38.
